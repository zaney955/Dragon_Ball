# 天下第一武道会重制验收

日期：2026-10-10。地图继续使用 `budokai` / 选择索引 0，战斗边界保持 `{ x: 13.5, z: 6 }`。

## 实现

- 独立的 `src/world/budokai.js` 使用当前 Three.js 与 MeshToonMaterial，接入原有选图、图鉴、场景释放与破坏系统。
- 主会馆采用双层四坡曲面金瓦屋顶，包含密集瓦脊、厚檐、木构托架、红梁柱、凹入窗格和侧翼会馆。牌匾包含厚木底板、三层红色框线、角钉与红描边中文。
- 门楼使用带倒角的挤出石材、拱门、台阶、分层红色浮雕嵌板、卷草、花纹和立体鬼面。鬼面的曲线尖角、眉、眼、鼻、牙齿、口腔和耳部均为几何体。入口白帘有真实褶皱。
- 原有 98 块可破坏石砖保持独立，砖缝、倒角、台阶、厚重台基、侧面分砖与细小裂纹得到重建。12 个原有可破坏石、木、陶道具移至擂台外侧的服务通道，仍沿用相同生命值和破坏行为。
- 两侧四层看台共有 192 名三维观众，配合石红围栏、鬼面前栏、4 面动态红蓝旗、4 把曲面蓝色流苏伞、服务桌及市集摊位。
- 柏树、棕榈、灌木、起伏的远景草坡、4 组曲面山体、城市建筑和球形观景塔形成空间层次。180 个云朵实例缓慢流动，旗帜使用顶点变形，门帘轻摆。
- 按材质和空间分组保留索引合并静态几何，观众及枝叶复用实例。地图自己的天空材质不参与曝光映射，建筑沿用游戏卡通渲染与光照。支持晴日、暖夕、满月夜。
- 门楼位于 z=-14.5，看台位于 x≈±21.5 起，中央和镜头退让区域保持开放。远景、云层和低矮围栏不参与战斗镜头阻挡。

- 首页选图、十四角色图鉴、荒野 / 龟屋的桌面及手机破坏回归、天神殿镜头 / 玩法 / 资源清理：8 / 8 通过。

最终侧面全景采样为 187 次绘制调用、2,172,710 个提交三角形（包括阴影通道）、47,753,372 字节几何属性与索引（45.54 MiB）。此数值是场景几何预算，不是浏览器进程总内存，也不代表所有战斗特效的峰值。沿用原有破坏回归的 400 次绘制上限，大范围破坏场景亦通过。

连续地图切换的最终结果：实例缓冲释放事件 9 次、几何释放事件 913 次；三轮结束均为 199 个 GPU 几何、13 个纹理，未增长。材质合并使用顶点颜色，观众与枝叶使用实例颜色，保持原有表面色差。

回归过程中发现并修复了大范围破坏后绘制调用超过原有预算的问题；通过合并静态彩色材质批次和同几何的彩色实例，保留模型细节并使回归通过。首轮直连验收在大厅连接阶段失败（本地代理 EPIPE / 房间未加载），中继通过；预热本地 Worker 后重跑进入战斗，但在并行几何单测占用 CPU 时触发自动中继。加入静态场景缓存并单独运行真实直连验收，最终通过（0 条中继消息）。

## 进场缓存

每个应用上下文保留一个未破坏的静态场景模板。重复建图实测 5.37–7.79ms，避免在联机进场时重新挤出和合并数千个装饰构件。场景节点、材质、旗帜顶点与天空颜色缓冲每场独立；不会继承上一场的破坏或光照。新增单测覆盖此隔离。

静态几何和纹理图像在 CPU 中有界缓存，场景退出仍释放 GPU 几何、纹理和实例缓冲。缓存为每个上下文一份，静态顶点数组在当前武道会场景与模板之间共享，不复制整张地图的数据。未将静态资源标记为不可释放的全局 GPU 资源。
